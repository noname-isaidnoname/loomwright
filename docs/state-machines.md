## Implicit-state fixes in this pass

Three transitions were changed from "logical state first, physical state
maybe" to a single authoritative transition:

- `OutputArbiter::acquire` injects the shared down before recording the owner;
  a failed injection leaves no claim, so the next claimant still injects.
- `OutputArbiter::release` restores the owner if the up injection fails, so the
  still-held key can be released by a later retry, client drop or shutdown.
- Held-loop bookkeeping uses a per-task ticket. Key-up erases the map entry
  before the cancelled frame unwinds; without the ticket, an immediate re-press
  would have its new entry erased by the old frame's guard and two held loops
  would tick at once.

The scheduler/task, cancellation, evdev recovery, passthrough, GUI and picker
state machines were traced as well; no further concrete transition bug was
found in this pass. The residual gaps below still need hardware or compositor
evidence.

## GUI connection-loss investigation

libX11 treats `_XIOError` as fatal. A preflight `poll` cannot protect an Xlib call against a disconnect that occurs after the check, and a non-local jump out of Xlib would skip C++ cleanup and may leave library locks held. The panel now uses XCB rather than Xlib, with no process-wide X error handler.

`src/xcb_connection.cpp` provides an RAII XCB transport with explicit connection error inspection and idempotent close. The integration test stops its private X server, kills it with an XCB reply pending and a production `GuiHost` starting up, and checks both error reporting and fd cleanup. The separate mouse-position picker also uses this transport; its integration test kills its private X server while the picker is issuing requests.

## Real desktop shared-input verification (2026-11-28)

Environment: Wayland session (`XDG_SESSION_TYPE=wayland`, `WAYLAND_DISPLAY=wayland-1`) with an Xwayland `DISPLAY=:0`, `/dev/uinput` writable. A temporary, udev-classified uinput keyboard (`ID_INPUT_KEY=1`) named `Verification Keyboard` was created and passed to both scripts with `--input-device`. No physical laptop key was injected. An `xev` window on the real Xwayland display was focused to observe desktop delivery, and separate evdev watchers read the broker's `Loomwright passthrough` node and the original virtual keyboard node.

Scripts: `verify-a` consumed F13; `verify-b` consumed F14; both set `option panic = "F24"` and only logged their own edges. Both were started with default `--input-mode auto` against the same event node.

Evidence:

1. F13 down/up appeared only in `verify-a`'s log (`A F13 down`, `A F13 up`); F14 down/up only in `verify-b`'s log. The passthrough watcher saw neither code, while the watcher on the grabbed physical node saw no `EV_KEY` at all. The broker socket existed in `$XDG_RUNTIME_DIR` while both scripts ran.
2. F24 down/up appeared on the passthrough watcher as `EV_KEY 194 1` / `EV_KEY 194 0` and in focused `xev` as `KeyPress`/`KeyRelease` with `keysym 0xffd5, F24`. Both scripts logged `Panic key F24 pressed` and stopped. `EVIOCGKEY` on the virtual keyboard was empty afterwards: no stuck key.
3. After that panic stop, the broker socket was gone. Two new scripts were started and stopped with SIGTERM while no key was held; the socket disappeared again and a direct evdev watcher then saw F24 down/up from the original virtual keyboard, proving the `EVIOCGRAB` had been released.
4. With two new scripts running, A (`EV_KEY 30`) was held so it passed through, then the virtual keyboard was destroyed to simulate disconnect. The passthrough watcher recorded `EV_KEY 30 1` followed by `EV_KEY 30 0`; both scripts logged `Input device ... disconnected`; focused `xev` ended its A events with a `KeyRelease` (`keysym 0x61, a`). Xwayland's normal autorepeat produced additional A press/release pairs while the key was held; the last event was a release. No `Verification Keyboard`, passthrough node, broker socket, or test process remained.

Not covered by this run: the physical laptop keyboard, startup handoff with a key already held, other compositors, and real-desktop delivery of output synthesized by two scripts at once (the deterministic `output_broker` test covers the injection and held-state rules). Broker `SIGKILL` while a key is held is covered only by the isolated `evdev_shared_broker` test.
